# Как раздавать приложение без App Store / Google Play

Для **теста и показа** (демо, пилот, заказчику) не обязательно публиковать в сторах.

---

## Android — самый простой вариант

**Никакого аккаунта разработчика не нужно.**

1. Соберите APK с адресом вашего облачного API:
   ```bash
   cd mobile
   # Подставьте URL вашего облачного бэкенда
   flutter build apk --release --dart-define=API_BASE_URL=https://ваш-сервер.com
   ```

2. Файл появится здесь:
   ```
   build/app/outputs/flutter-apk/app-release.apk
   ```

3. Как раздать:
   - Отправить файл в **Telegram / WhatsApp / email**
   - Или залить на **Google Drive**, **Dropbox**, **Яндекс.Диск** и отправить ссылку

4. Установка у тестировщика:
   - Скачать APK по ссылке
   - В настройках разрешить «Установка из неизвестных источников» (для этого приложения или для браузера)
   - Открыть файл и установить

Так можно раздавать приложение всем, у кого Android — для показа и теста этого достаточно.

## iOS — варианты без App Store

### Вариант 1: Показать на своём iPhone (без платного аккаунта)

- Подключите iPhone к Mac по USB.
- В Xcode откройте проект `ios/Runner.xcworkspace`.
- Выберите ваш iPhone в списке устройств и нажмите Run (▶️).

Приложение ставится на ваш телефон и работает 7 дней (с бесплатным Apple ID). Для личной демонстрации этого хватает. Потом можно снова нажать Run в Xcode и «продлить».

### Вариант 2: Раздать тестерам через TestFlight (нужен платный аккаунт)

Пошаговая инструкция — ниже в разделе **«TestFlight: от создания приложения до ссылки тестерам»**.

## Сборка с облачным API (одна команда)

Перед сборкой подставьте **реальный** URL вашего бэкенда (без слэша в конце).

**Android (APK для раздачи):**
```bash
cd mobile
flutter build apk --release --dart-define=API_BASE_URL=https://api.ваш-домен.com
# Файл: build/app/outputs/flutter-apk/app-release.apk
```

**iOS (только для установки с этого Mac через Xcode):**
```bash
cd mobile
flutter build ios --release --dart-define=API_BASE_URL=https://api.ваш-домен.com
# Дальше в Xcode: Product → Run на вашем iPhone
```

## Сначала поставили на iPhone, потом подняли сервер в облаке — придёт ли обновление?

**Адрес сервера вшит в приложение при сборке.** Уже установленная версия не «узнает» новый URL сама — обновления конфига с сервера нет.

**Как сделать, чтобы все перешли на облако:**

1. Поднять бэкенд на облачном сервере.
2. Собрать **новую версию приложения** с URL облака:
   ```bash
   flutter build ios --release --dart-define=API_BASE_URL=https://ваш-облако.com
   ```
3. Загрузить эту сборку в App Store Connect (Archive → Upload), как в инструкции по TestFlight.

В TestFlight эта сборка появится как **обновление**: тестеры откроют TestFlight, увидят «Доступно обновление» и установят его. После установки приложение уже будет ходить на облачный сервер.

**Итого:** обновление придёт только как **новая сборка приложения** (с новым URL внутри), а не как автоматическая смена адреса. Порядок может быть любой: сначала раздали с локальным URL, подняли облако — потом выкатили новую сборку с облачным URL, и все обновляются через TestFlight.

## Кратко

| Цель                         | Решение                                      |
|-----------------------------|-----------------------------------------------|
| Показать заказчику/команде  | **Android:** раздать APK по ссылке/в мессенджер |
| Показать на своём iPhone    | Запуск из Xcode по USB (без App Store)        |
| Дать iOS-версию тестерам    | Нужен Apple Developer ($99/год) → TestFlight  |

Для «тестово чтобы показать» обычно достаточно: **облачный бэкенд + раздача Android APK + показ iOS с вашего Mac.**

## TestFlight: от создания приложения до ссылки тестерам

Кратко, без лишней документации. У вас уже есть платный Apple Developer.

**1. Зарегистрировать App ID (если ещё нет)**  
→ developer.apple.com → Account → Certificates, Identifiers & Profiles → Identifiers → +  
→ App IDs → Continue → App → описание: Tutas Ai Mobile, Bundle ID: **Explicit** → `com.example.tutasAiMobile` (или свой, например `com.вашакомпания.tutasai`) → Register.  
В Xcode в проекте Runner должен быть тот же Bundle Identifier.

**2. Создать приложение в App Store Connect**  
→ appstoreconnect.apple.com → Мои приложения → + → Новое приложение  
→ Платформа: iOS. Название: Tutas Ai Mobile. Язык: основной. Bundle ID: выбрать тот, что создали. SKU: любое уникальное (например tutas-ai-mobile). → Создать.

**3. Собрать архив в Xcode**  
→ В проекте `mobile` в терминале:  
`flutter build ios --release --dart-define=API_BASE_URL=https://ваш-сервер.com`  
→ Открыть `mobile/ios/Runner.xcworkspace` в Xcode.  
→ Сверху выбрать **Any iOS Device (arm64)** (не симулятор).  
→ Меню **Product → Archive**. Дождаться окончания.

**4. Загрузить в App Store Connect**  
→ Откроется Organizer. Выберите только что созданный архив → **Distribute App**  
→ **App Store Connect** → Next → **Upload** → Next. Оставьте галочки по умолчанию → Next → Upload.  
→ Подождать 5–15 минут: в App Store Connect в разделе приложения появится сборка в TestFlight.

**5. Включить TestFlight и добавить тестеров**  
→ App Store Connect → ваше приложение → вкладка **TestFlight**.  
→ Сборка появится в «iOS». Если нужно — заполнить «Что нового» и нажать **Предоставить доступ к тестированию**.  
→ Слева **Внутренняя группа** или **Внешняя группа**.  
→ Внутренняя: до 100 тестеров из вашей команды (добавляются по email Apple ID).  
→ Внешняя: до 10 000 по email, первый раз нужно отправить сборку на проверку (1–2 дня).  
→ Добавить тестировщика: + → ввести email (Apple ID) → Добавить.  
→ Тестеру на почту придёт приглашение; он устанавливает приложение **TestFlight** из App Store, принимает приглашение и оттуда ставит ваше приложение.

**Готово.** Ссылку на приложение в TestFlight можно не отправлять — тестеры получают доступ по приглашению на email.
