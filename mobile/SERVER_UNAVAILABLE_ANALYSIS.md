# Глубокий анализ: «Сервер недоступен» на телефоне

## Что уже проверено

1. **Backend запущен** — `curl http://localhost:8000/health` с Mac возвращает OK.
2. **Порт 8000 на Mac** — слушает на `*:8000` (все интерфейсы). Есть входящие соединения с `192.168.49.63` на `192.168.49.65:8000`, т.е. доступ из LAN возможен.
3. **mobile/.env** — содержимое: `API_BASE_URL=http://192.168.49.65:8000`, без лишних пробелов.
4. **iOS** — в Info.plist добавлен NSAppTransportSecurity (разрешён HTTP).
5. **Таймауты** — в AuthService заданы connect/receive timeout.

---

## Возможные причины (по приоритету)

### 1. Приложение использует старый .env из сборки

Во Flutter файл `.env` попадает в приложение как **asset на этапе сборки**. Если вы поменяли `.env` после последней сборки и только перезапустили приложение (Run в Xcode или hot reload), в бандле остаётся **старый** URL (например `localhost:8000`).

**Что делать:** после любого изменения `.env` обязательно:
```bash
cd mobile
flutter clean
flutter pub get
```
Затем снова запустить приложение из Xcode (или `flutter run`). Без полной пересборки новый `.env` не подхватится.

---

### 2. Что реально видит приложение (URL)

Внизу экрана входа в **режиме отладки** выводится строка вида: `API: http://...`

- Если там **`http://localhost:8000`** — приложение не видит ваш `.env` (см. п.1: пересборка после изменения `.env`).
- Если там **`http://192.168.49.65:8000`** — URL правильный, проблема скорее в сети или на устройстве (п.3–4).

---

### 3. Телефон в другой сети

Телефон должен быть в той же Wi‑Fi сети, что и Mac (тот же роутер). Если включён «Сотовые данные», приложение может уходить в интернет, а не в локальную сеть; для теста лучше отключить сотовые данные и оставить только Wi‑Fi с тем же роутером, что и у Mac.

---

### 4. Firewall на Mac

Системные настройки → Сеть → Firewall: если включён, нужно разрешить входящие для «Docker» или для порта 8000. Можно временно отключить Firewall для проверки.

---

### 5. Docker Desktop и доступ с LAN

На части машин Docker Desktop пробрасывает порты только на localhost, и с телефона по IP Mac порт не открыт. На вашем Mac по выводу `netstat` порт 8000 слушает на всех интерфейсах и есть соединения с другого устройства (192.168.49.63), значит в текущей конфигурации доступ с LAN есть. Если у вас другой компьютер — стоит проверить: с телефона в Safari открыть `http://ВАШ_IP_MAC:8000/health`. Если страница не открывается — порт с LAN до Mac не доходит (firewall или особенности Docker).

---

### 6. Загрузка .env как asset

В коде:
- `pubspec.yaml`: `assets: [.env]`
- `main()`: `await AppConfig.load();` → `dotenv.load(fileName: '.env');`

Путь указан верно (без `assets/`). Важно: при сборке в бандл попадает файл `.env`, который лежит в корне проекта (рядом с `pubspec.yaml`). Если вы редактировали другой файл (например, в корне репозитория, а не в `mobile/`), приложение его не увидит.

## Диагностика по шагам

1. **Проверить URL в приложении**  
   Запустить в debug, на экране входа посмотреть строку `API: ...`. Записать значение.

2. **Проверить доступ с телефона в браузере**  
   На iPhone в Safari открыть: `http://192.168.49.65:8000/health`  
   - Если открывается JSON — сеть и порт в порядке, проблема в приложении (скорее всего старый .env, п.1).  
   - Если не открывается — проблема между телефоном и Mac (сеть, firewall, другой IP).

3. **Убедиться, что правильный .env в mobile/**  
   В терминале:
   ```bash
   cat "/Users/kuralbekadilet475/Tutas Ai/mobile/.env"
   ```
   Должно быть: `API_BASE_URL=http://192.168.49.65:8000` (без пробелов вокруг `=`).

4. **Пересобрать приложение после смены .env**  
   В папке `mobile`:
   ```bash
   flutter clean && flutter pub get
   ```
   Затем снова запуск из Xcode (или `flutter run`).

5. **Проверить актуальный IP Mac**  
   Если роутер перераздал адрес, IP мог поменяться:
   ```bash
   ifconfig | grep "inet " | grep -v 127.0.0.1
   ```
   Использовать актуальный адрес вида `192.168.x.x` в `.env` и снова пересобрать приложение (п.4).

## Что добавлено в код для диагностики

- После загрузки конфига в `main()` в консоль выводится строка с фактическим `API_BASE_URL`. По ней в логах Xcode/Flutter можно убедиться, какой URL реально использует приложение при старте.
- При ошибке «Сервер недоступен» в сообщении показывается URL, по которому шёл запрос; тот же URL стоит проверить в Safari на телефоне.

Если после полной пересборки (п.4) в приложении отображается `API: http://192.168.49.65:8000`, а в Safari на телефоне `http://192.168.49.65:8000/health` открывается — но логин всё равно даёт «Сервер недоступен», пришлите точный текст ошибки и, по возможности, фрагмент логов из Xcode в момент нажатия «Вход».

## Если http://ВАШ_IP:8000/health не открывается в Safari на телефоне

Значит до Mac по сети порт 8000 недоступен (Docker на Mac часто пробрасывает порты только на localhost).

**Решение: запустить бэкенд на Mac (не в Docker), чтобы он слушал на всех интерфейсах.**

1. Поднять только БД и сервисы (без backend):
   ```bash
   cd "/Users/kuralbekadilet475/Tutas Ai"
   docker compose up -d db redis minio minio-init
   docker compose stop backend
   ```

2. Запустить бэкенд на хосте (из корня проекта):
   ```bash
   ./scripts/run_backend_local.sh
   ```
   Нужны Poetry и зависимости: `cd backend && poetry install` (если ещё не ставили).

3. В Safari на телефоне открыть `http://192.168.49.65:8000/health` — должна открыться страница с JSON.

4. В приложении снова нажать «Вход» или «Проверить сервер».
